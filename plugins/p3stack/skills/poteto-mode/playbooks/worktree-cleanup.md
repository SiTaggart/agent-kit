### Worktree and simulator cleanup

Read the installed plugin's [RUNTIME.md](../../../RUNTIME.md) first. Its native tool, model, path, and session-authorization rules apply. The user merges; this port never merges, enables auto-merge, or enters a merge queue.

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh <repo> <host>` (`codex` or `claude`) from this installed skill's absolute directory (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one in the host's managed worktree directory (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest project-scoped host session that touched it, then suggests a bucket. Claude runs mark history unknown; check scoped session usage separately per the adapter. A missing history result is not proof that a worktree is unused.
2. The bucket is advice, not permission. The pinned and active tasks are the real artifact (principle-prove-it-works). Read that set with the native task-list tools or get it from the user and cross-check every candidate. Upstream's `safe` bucket is `review-merged` in this port; a merged PR or old task never grants deletion authority. The pinned set wins, and missing task evidence is unknown.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out within the native concurrency limit to read project-scoped host session history and report whether the task is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned task spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Discover history and validate project metadata per RUNTIME.md.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and use the user's decision, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. Untracked files are also a hold, not assumed throwaway; name them. Deletion requires authorization for the concrete paths and any local work to be lost. Reuse authorization already given. Clean, merged, old, or not-in-use never supplies it.
5. Prune the confirmed set. Recheck each authorized path immediately before `git worktree remove <path>`. If it refuses because local work or ignored files remain, inspect and report those paths rather than force removal. Do not erase leftover directories. Branch refs survive. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. Inventory XCTestDevices clones, unavailable simulators, and old runtimes with `xcrun simctl list` and `xcrun simctl runtime list`. Within the user's concrete cleanup scope, remove only the identified targets using the simulator tool's supported delete commands. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, and package caches (pnpm, uv, brew, yarn). Do not guess application state or cache paths to delete. Preserve caches outside the authorized scope and anything the user asked to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
