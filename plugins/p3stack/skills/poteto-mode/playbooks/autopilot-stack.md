### Autopilot-stack

Read the installed plugin's [RUNTIME.md](../../../RUNTIME.md) first. Its native tool, model, path, and session-authorization rules apply. The user merges; this port never merges, enables auto-merge, or enters a merge queue.

**You own the verified PRs, never the landing. Run the Autopilot-full loop, but do not merge. Hand the operator the verified PRs to review and land. Stack a PR only when it builds on another PR.** The user merges in both.

1. **Run the owner loop unchanged.** Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr ...` for PR create, edit, view, watch, and merge operations. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). One native subagent in an exclusive local worktree per PR owns its change end to end: build, first push, a ready PR opened before self-proof, self-proof (gates, CI, receipts), skeptical Bugbot triage per `../references/bugbot-triage.md`, a slop-strip (the bundled **deslop** skill), `/no-comments` (the **no-comments** skill), and babysit to green per `playbooks/babysit.md`. Owners parallelize within the native concurrency limit when the work is self-contained. Within about 15 minutes, every owner starts a `.ai/decisions.tsv` trail per the **show-me-your-work** skill, pushes its first branch snapshot, and opens the PR ready, never draft. After that, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). Keep the trail uncommitted and return it in the report. Owners also keep the `.ai/children.tsv` of Autopilot-full step 2.
2. **Audit on a real loop.** The root runs an audit tick every hour. Use a native recurring check for the requested recurring program and confirm it was created, per Autopilot-full step 6. During an active turn, use bounded waits and status tools. If the host has no scheduler, report that unattended wakeups are unavailable and leave a durable resume point; do not invent a terminal sentinel or cloud-sleeper chain. Never leave the cadence to memory or lossy completion notifications. At each tick, re-read this installed playbook at its absolute plugin path and audit the operation against it. Fix drift during that tick. Probe each owner with a generic liveness or status check. Count only side effects as progress: commits, pushes, PR or check deltas, and store reports. Treat a lane that passes its expected runtime without a side effect as suspect. Inspect its current native status before replacing it, per Autopilot-full step 6. An observation timeout is not terminal.
3. **Hold the operator gates.** State-then-wait, so a request to state the plan is not a go. On the operator's explicit go, use the native goal tool with the full program objective only when the user explicitly requested a goal; otherwise record the objective in the program store. When a native goal is active it continues across turns until the chain is done. On the operator's stop, every owner takes an immediate zero-writes hold.
4. **Verify each round.** The owner reports its code-ready head SHA once the shipped code is final, and STACK-READY with the exact head SHA when its loop is green. The root verifies each round per Autopilot-full step 4, with STACK-READY in place of merge-ready. Nothing enters the stack unverified.
5. **Stop at verified, never ship.** No owner merges, arms auto-merge, or closes. A clean verdict hands the PR to the operator. After that handoff, nobody pushes without the operator's go.
6. **Stack a PR only when it builds on another PR.** Independent PRs stay based on trunk. When a PR builds on another, the root is the only topology writer. Owners push only their own branches and report the tip, current base, and intended parent. To stack a PR, fetch the intended parent, rebase the child branch onto that exact parent tip, push with `--force-with-lease` only after an `ls-remote` check, and set the PR base to the parent branch. Create it with `origin pr create --status open --base <parent-branch>` or `gh pr create --base <parent-branch>` according to the resolved forge. Retarget an existing PR with `origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`. Only the root PR targets trunk. In place of a rebase onto trunk, each stacked PR rebases onto its parent, and the stack root rebases onto trunk. A new head on the lower PR restacks the PRs above it. A PR whose `git patch-id` the restack leaves unchanged keeps its verdict. Never submit or register the chain through `gt`.
7. **Absorb drift at the root, then re-verify what moved.** The root fetches current trunk. An independent PR rebases onto trunk. A stack rebases from the bottom to the top, each PR onto its parent. When a rebase surfaces conflicts in an owner's files, that owner fixes its own slice and the root pushes the result. A rebase rewrites every SHA above it and voids verdicts at the old SHAs. Apply the patch-id rule in `playbooks/shipping.md` at each verdict SHA. Anything that is no longer valid goes back through this playbook's step 4 before delivery. Re-run mergeability and CI after every rewritten push even when the patch-id is unchanged. The countersign rule is unchanged from Autopilot-full. A genuinely new pin raises a stop for the root's fresh countersign. Absorbing drift of landed values is not a raise.
8. **Deliver the PRs.** The deliverable is the verified PRs. Each one carries its verifier verdict in the PR body or a comment. A stack is reviewable bottom-up. An independent PR targets trunk. The operator reviews and lands them. The user performs every merge.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and the user wants separate merge-ready handoffs. Autopilot-stack when the operator lands the PRs. A PR in that queue stacks only on a PR it builds on.

**Reply:** catch the operator up per the **ketchup** skill, with links to the stack root and tip, a one-line verdict per link, and anything parked or excluded with the reason.
